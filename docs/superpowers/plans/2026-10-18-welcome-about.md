# A welcome, Settings → About, and Settings in order of use — Implementation Plan

**Asked for by the user on 2026-10-18:** "for first time users maybe a short intro of what annai is, what it can do, and why is it safe to put in model keys here? also in settings maybe there shall be an about page that have the license and repo location and related information? and maybe in the intro we may also want a legal disclaimer?" Brief: `.superpowers/briefs/welcome-about.md`. Folded in by the coordinator the same day: a link to get a Jina key, Settings in the order a user reaches for them, and Settings → Experimental with swiping between tabs, off by default.

## Choices this plan makes

1. **The welcome is a screen, `#/welcome` (steps `#/welcome/2` to `#/welcome/5`), not a dialog over the app.** The top bar stays, so it never blocks the user (spec §2 principle 4), Back goes to the step before, and every step is a link a keyboard reaches in order. Five steps: what annai is, what it can do, your keys and data, the fine print, get started.
2. **It shows the first time annai opens at its start:** `/` with no screen in the address (the manifest's `start_url`). A link that opens a screen is never interrupted: a shared trip (`#import=…`), a share (`#/import?inbox=1`), OpenRouter's sign-in coming back (`?code=…`), or any other `#/…` link. The welcome then waits for the next plain start. `main.js` decides before the shell's first draw and replaces the address with `#/welcome`, so there is no flash of Trips.
3. **Remembered in the app's settings,** `welcomedAt` (ms) in `sys:settings` `/app.json`, written when the welcome is first drawn, so it is shown once per device; nothing is kept in localStorage. Erase brings it back, as on a new device. The iPhone Home Screen app has storage of its own, so it shows there once too, which is where the model gets set up.
4. **No test switch in the shipped code.** The e2e helper `openApp` opens `#/trips` by default instead of `/`, and the seven tests that opened `/` directly open `/#/trips` (the same request: the hash isn't sent). Only the welcome's own tests open the plain start.
5. **One Shiori.** The welcome shows no second avatar: the dock stays (spec §16.2: one Shiori per screen, the dock on every screen), and the first step points at her there.
6. **The last step is the existing onboarding:** where annai isn't installed, the install guide (the warning's steps, and on Android its Install button, from `install.js` helpers both use; the warning itself waits while the welcome is on screen); then Settings → Models, with Sign in with OpenRouter. On an iPhone in Safari it says to install first and set the model up in the Home Screen app, since the two keep separate data.
7. **"Skip"** on steps 1 to 4 goes to the last step, which offers "Set up a model" and "Look around first" (Trips).
8. **Focus moves to each step's heading** (`tabindex="-1"`), after the shell has put the screen in place. Nothing in it moves, so reduced motion has nothing to stop (a fade between steps stuck at its start in WebKit's first draw, showing nothing, so it went).
9. **The copy about keys and data, and the fine print, are one module** (`src/ui/privacy.js`) that the welcome and About both draw, so they can't drift. Every claim is checked against the code; the report lists each with its code.
10. **Settings → About is `#/about`:** annai, its version and the build of the service worker that is running (the page asks it, through a `MessageChannel`, with a new `build` message in `sw.js`; before one controls the page it says so); the licence, read in annai at `#/about/licence` from a shipped copy of `LICENSE` (now in the service worker's shell, so it reads offline); the source at https://github.com/annai-guide/annai; issues at https://github.com/annai-guide/annai/issues; the same keys-and-data summary and fine print; "Show the welcome again"; and the credits.
11. **Credits are data** (`src/ui/credits.js`): each data source with what annai uses it for, the hosts it is reached at, and the attribution its licence or policy asks for, with links; the fonts (SIL OFL 1.1, read in annai at `#/about/fonts` from the shipped `OFL.txt`); Shiori's art, drawn for annai.
12. **A unit test finds every host named in annai's shipped code** (the shell's JavaScript, `sw.js` and `plugins-official/`) and fails unless it is a credited source, a provider from `catalog/templates.json`, or on a short list of hosts that aren't sources, each with its reason (annai's own, links the user opens, places the user adds). A new source can't ship without a credit.
13. **Attribution where it's shown.** annai draws no map tiles anywhere (Replay's map is the route alone), and its own screens show OpenStreetMap and Wikipedia data only in the offline pack panel, which already credits them. Place names from the pack (Now, the Live chip, Replay, stamps) are names, which OSMF's guidelines treat like geocoding results: credited by the app, not at each name. Open-Meteo's licence asks for a link next to wherever its data is shown: annai shows it only in the Trace, as the weather tool's answer, so that answer now starts with "Weather data by Open-Meteo.com (https://open-meteo.com/, CC BY 4.0)".
14. **Settings in order of use:** the update first while one waits ("Restart annai"); then Models, Voice, Notifications, Backup (with "Open an annai file" in it), Shiori, Photos, Tools, Plugins and plugin pages, Storage; then About (whose line carries the version, which the App section showed), Diagnostics, Developer, Experimental, Erase. Photos moves down because it is a long form most people set once.
15. **Settings → Experimental (`#/experimental`):** "Features that are still being tried. They may have bugs, and their fixes may come slower than the rest of annai." Its first switch, "Swipe sideways to move between tabs", is `experimental.swipeTabs` in `/app.json`, off by default. The shell reads it at start and when the switch changes (`ctx.setSwipes`); off, the swipe handler does nothing and `.view` has no `touch-action` (the `swipes` class carries `pan-y pinch-zoom`). The page is a list of panels, so the remote trace plugin's line can join it.
16. **The page-persistence bug:** swiping into a tab always opened that tab's first screen, at its top, so swiping away from Settings → Models and back left you on Settings, scrolled to the top. Now each tab remembers the screen you last had open in it and where you were on it, and swiping into the tab brings you back there. Tapping a tab in the top bar still opens its first screen.
17. **The Jina link:** Settings → Tools links "Get a free key from Jina" to https://jina.ai/api-dashboard/key-manager (its "Manage API Key" page), a real link with `target="_blank"` and `rel="noopener noreferrer"`. The backup place's help link gets `noreferrer` too. "Get a key" on an endpoint (`src/ui/screens/endpoint.js`) is in openai-responses' files: listed, not changed.
18. **Spec:** §16.2 gets the welcome in Onboarding, About and Experimental in Settings, and swiping as experimental and off by default; §15 gets the attribution rule.
19. **Ledger** in the worktree's own git-ignored `.superpowers/sdd/welcome-about/progress.md`.

## Tasks (test-first)

1. **Welcome decision and memory** (`src/ui/welcome.js`): `plainStart({ hash, search })` and `shouldWelcome(ws, location)`; unit tests. `main.js` replaces the address before the shell starts.
2. **Welcome screens** (`src/ui/screens/welcome.js`), `install.js` helpers, CSS. e2e (`test/e2e/welcome.spec.js`, both browsers): a fresh device opening `/` sees it, once (a reload of `/` doesn't); `#import=<url>` and `#/import?inbox=1` open the import screen with no welcome, and the next plain start shows it; every step reachable with the keyboard alone, focus on each heading; at 320 px nothing scrolls sideways on any step.
3. **The build from the service worker:** `sw.js` answers `build` on the port it is sent; unit test through `vm` as `sw-shell.test.js` does; `LICENSE` in the shell (its test's list).
4. **About** (`src/ui/screens/about.js`), `credits.js`, `privacy.js`; the licence and font texts. e2e: the build matches `sw.js`, the licence and source links, every credit, Show the welcome again brings it back, 320 px fit.
5. **The sources test** (`test/unit/credits.test.js`).
6. **Open-Meteo's credit** in the weather answer (`test/unit/plugin-places.test.js` first).
7. **Settings order, Experimental, swiping off by default, the persistence fix:** phone-fit's swipe tests turn the switch on first; a test that it is off by default (no tab change, `touch-action` auto); a test that swiping back into a tab returns to its last screen and scroll; a test of the Settings order.
8. **The Jina link:** e2e on Settings → Tools.
9. **Spec** §15 and §16.
10. `npm run stamp && npm run check`, the full Docker e2e, screenshots in WebKit at 420 px, light and dark.
