# Lessons

What this project's past changes taught us. Read all of this before changing an API, a format or an
agreed behaviour here. For the full story of a line, find the entry with the same date and name in
`lessons-full.md`; a merged line names each of its entries.

When one has to change, add the full entry to `lessons-full.md` and one line here, newest last, in the
same commit as the change. Keep this file under 20 KB: at the cap, merge lines before adding.

- **2026-10-23 annai's translation TSV: a note part for the translator**: when a file is written by a tool and by people, give each writer a part the other never touches.
- **2026-10-26 annai: modules pass data, and words are made at display; 2026-10-27 annai: a choice keeps its value and its words apart**: pass data between modules (kinds, flags, values, ids), and make whole sentences only where they are shown; a choice has its value and its words apart from the start, even while they are the same. Never match on words a person reads.
- **2026-10-27 annai: plain fields are English, `shown` holds the screen's words; 2026-10-27 annai: an error carries which of its words are a developer's English**: when one value has two audiences, the field the machine or model reads is the default and the human-facing one the optional extra, so a forgotten extra shows as English on screen, where people notice it, instead of leaking; when its language matters to whoever shows it, the value carries that fact (a flag, or the part that differs), set where it is made: a comment in the source reaches no reader.
- **2026-10-27 annai: a new record always writes the field that tells it from an old one; 2026-10-29 annai: keep a reading's uncertainty per field, where the user acts on it**: when later code must tell old records from new ones, write the field on every new record, with `null` for empty, and test for the key, not its value: a record without it can only be an old one. Record a model's uncertainty at the level the user acts on, not as one flag over the whole record.
- **2026-10-27 annai: an error's optional parts go in one options object from the start; 2026-11-09 annai: twoStep's optional parts in one options object**: in any function other modules call (errors, UI helpers), anything optional after the required arguments goes in one options object, even when there is only one so far. A new optional part then changes no caller.
- **2026-10-27 annai: a plugin's `api` is the oldest host it needs, not an exact match**: a version a component declares about its host is the minimum it needs. The host accepts anything at or below its own, and the number is raised only when the component starts using something an older host lacks.
- **2026-10-27 annai: a name the screens show is read from what is stored, not from what happens to be running; 2026-11-10 annai: a page at its end is read as the dock changes, not remembered**: read a fact where and when it is needed, from the stored source of truth, even if the call becomes async; a cache or a network copy is only for when nothing is stored. Keep a memory only where the fact can't be read then, name what makes it stale, and where staleness can't be read, let it fail toward doing nothing. Before keying a rule on a value, look at when each engine updates it.
- **2026-10-28 annai: an official plugin's translations are not files of its package**: when a unit you version and verify whole carries parts each user needs only one of, or parts that change on their own schedule, give those parts their own hash and fetch path from the first version, keyed by what selects them.
- **2026-10-28 annai: what a model makes of a stored file is kept beside it, and an explicit ask redoes it**: keep derived content that later requests need with its owner, named by what it was made from (a content hash), and let an explicit ask redo it, newest wins.
- **2026-10-29 annai: mark both ends of a move on their records; 2026-11-09 annai: a file's moves are undone as one chain, and Undo's count is her writes alone; 2026-11-10 annai: a move is one transaction across its two scopes**: when one operation spans two records, write the relation on both, and mark what an undo writes, so later decisions never take it for the user's own work; reverse a sequence of them on one thing as one sequence, in order from the records both ends keep, never step by step from guesses about the present. Marks say what happened; only one commit makes it all-or-nothing: an operation that must land whole is one transaction, whatever store partitions it spans, so the write API takes changes across partitions from its first version. A count in a record counts one kind of thing, whichever side writes it, and not what another field already says.
- **2026-10-30 annai: a provider's reply is kept as it came, beside annai's reading of it; 2026-11-10 annai: a provider's rule for the sequence it is sent is enforced where the request is built, over whatever is stored**: when a provider checks what is sent back, its reply is kept as it came, beside annai's own reading of it, and the requests of one exchange are append-only (annai's parts are for annai and for other models); when it defers a call it makes itself, the rule for what may follow is enforced in the one place that builds the request, working from the stored history, so a fix reaches conversations already stuck and no stored format changes. Ask the real API for every shape, and give the stand-in the same refusals.
- **2026-10-30 annai: a native reply goes to the models that can read it, and a refusal is read by status**: scope what a provider returns to who can read it, not to where it was fetched; act on a request's status and on what was sent, not on an error's text.
- **2026-11-01 annai: a log's last number never goes back**: when anything compares a position in a log, removing entries must still move the position forward; give removal its own entry rather than rewinding.
- **2026-11-02 annai: live Koe gets `sleep` back (plan decision 29 reversed); 2026-11-05 annai: voice, four changes from the second drive; 2026-11-11 A note cut mid-turn is asked for again**: never let a wait or an end depend on a signal the other side may not send, or on its absence: bound it, say what a late one means, and give it a second way out (a decision by whoever can judge, or an explicit command); an end sent in place of the usual one is an end too. A threshold learned from outside sound never takes one sample as truth. Recording and sending are separate steps. "It worked once" isn't a state: keep the way back armed. Test a real tool call before shipping a model: a clean open proves nothing.
- **2026-11-04 annai: a "moved" watch counts from when it was set, not from Shiori's last wake**: a watch or timer counts from its own start, and resets only on its own firing. Don't reset it from an unrelated event because that event seems to make it redundant: how often that event happens will change.
- **2026-11-05 annai: screen-on is one setting, and a tap in Auto holds voice for that exchange; 2026-11-05 annai: Auto voice removed; voice and Live are each one tap**: a direct action outranks an automatic mode, which decides what happens when the user does nothing, never what their tap means, and rests on a signal seen working on the real device, sayable in one sentence: one measured rule (driving, from GPS), and the rest a switch the user owns. A change of state is an event told once from its source, not worked out again from a value that can change for other reasons.
- **2026-11-05 annai: all a reload needs is one overwritten record; 2026-11-06 annai: a hold's date is in the drive record, and goes with its hold**: state a restart needs, anything that lasts past one event, is one record it reads from the start, written from one method, with values that must agree written together. A log is evidence, not state. A count that must survive is a counter, and each consumer records its own reading of it. A saved value that something can cancel is written when it is cancelled, not only when set: a copy that outlives what it belongs to is worse than none. Anything that wipes state stops its writers first.
- **2026-11-05 annai: a gate reads the conversation, not one line**: give a classifier the context a person would need. And give it a way to be wrong cheaply: here a wrong "for her" costs a short reply, while a wrong "not for her" loses what the user said.
- **2026-11-05 annai: a model its plugin dropped leaves Koe's Realtime list at the update**: removing something from a catalog isn't finished until you've read what saved settings do with it. List what names it, then decide each one's fate, and test through the update path, not only on fresh data. When two saves must go together and the store has a transaction, use it: there's then no order to get right. A rule that reacts to an update goes out a release ahead of it.
- **2026-11-05 annai: one path for a gap in GPS evidence; 2026-11-10 A reminder's time is one set of words, which both halves read**: one question, one place that answers it: what two readers state (a time) is put into words once, at the source (in the zone it was set in, with that zone named), and a reader that renders it again states a second answer. When fixes keep finding another disagreement between two places, take one away instead of syncing them. Cases that look different often decide the same way and differ in a few things you can name. A straight-line way can prove a drive went on, never that it ended.
- **2026-11-06 annai: what only tests call is unused**: a member kept for tests is shipped code that no operator runs. Tests go through the real path, or keep their helper to themselves. A test seam stays only when it resets module state or is an option whose shipped default has its own test; an option only a test passes left the shipped limit untested.
- **2026-11-06 annai: a take-over belongs to the shell, not to the screen it leaves**: what must happen wherever the user is lives in the one place that is always there. A screen's listener only works while that screen shows, and says nothing about the others.
- **2026-11-06 Trip dates and last talked on the scope record; 2026-11-10 list_trips gives each row when it was last talked in**: a record that lists things, or a list a model chooses from, carries what deciding among them needs (what a person's screen tells its rows apart by, the same value from the same source), not only what today's list shows or each row's name. A mirror has one writer per field and a key that says it was filled, so filling old records is one pass that ends. What can be read again from the source doesn't travel: an archive's copy could only be stale, or claim something. A tool whose every call costs the user an action says so.
- **2026-11-06 annai: looking isn't doing; 2026-11-10 A move carries the user's last line and her recap, and each end says where; 2026-11-11 open_trip asks with annai's card, and nothing moves by itself**: what the app acts on follows what the user did, not what's on screen: looking changes nothing that fires, reminds or takes over. What changes where the user is happens at their own act, never later by itself: when a step needs the user, ask, and do it at their answer, rather than starting it and guarding the wait against everything they might do meanwhile; a step that does wait for "later" checks again, when later comes, everything it acts on. A fix that adds a guard to a waiting state first asks whether the state can go. A new meaning gets an entry of its own, not an old one with a value an older reader shows wrongly; both ends of a move say it where the user looks, each in its own side's words.
- **2026-11-06 annai: a copy is held to its source, and to what stands still**: a copy that outlives what it was made from carries a digest of what it was made from, and each look compares that with the source itself, whatever screen is open. Make the digest from data alone: a sentence, a language, a clock or a position would call off a good copy. And a read that failed is "could not look", never "nothing there" and never a part result: a read answers or nothing changes, so nothing downstream has to know how much was read, and what failed tries again by itself.
- **2026-11-06 annai: the conversation has its own address; 2026-11-07 annai: Back and Forward skip what is gone**: an address names the thing it shows, not "the current one". A screen opens what it shows only when the user moved there, never on a redraw. An old address goes where it now means by the shell's own replace, so Back can't land on it and bounce. An entry that can't be shown is passed over in the direction the user was going, once, in the shell before anything draws, for every address naming the thing, and a move that passes entries passes those at the address it left too; that needs the history's order, so each entry carries its number beside its key, and a replace keeps it (`location.replace` drops `history.state`). Leaving a screen for good (Remove trip) goes the way Back goes, never forward to a new entry.
- **2026-11-06 annai: a tapped notification tells the open page which conversation**: when a page and its service worker ship apart, each message type does one job and carries what its receiver needs to act. The payload is outside text: the sender checks it by a strict rule, and the receiver uses it only as an address, which names nothing that isn't there and goes to the safe default.
- **2026-11-06 A chat is a trip with a draft flag**: a thing made ahead of need carries its own mark, written by what makes it and cleared by what spends it, and every list, export and automatic follower leaves it out. An older reader that doesn't know the mark shows it as an ordinary record.
- **2026-11-06 start_trip refuses in an undated conversation; 2026-11-10 open_trip works from an undated conversation**: when a thing becomes another by gaining a field, every guard that means "the other kind" tests that field, not the container both kinds share, and the tool that makes the other kind refuses where it is missing, naming the field and file to set. A change the model made for the user shows where they look, with Undo, read from the record that keeps the version before; a tool that moves the user says what stays behind.
- **2026-11-09 annai: an archive's times stay within a date's range**: a number that is read as a date has a date's range in the format's schema (±8.64e15 ms), and a file outside it is refused as damaged when it comes in, not guarded in each screen that draws it.
- **2026-11-09 Reading another trip is granted by annai, not by her; 2026-11-10 annai: the card hears words where they first exist, and no model's verdict decides it; 2026-11-11 A spoken yes is every clause on the list, and a card's buttons end at the first tap**: an approval comes only from what the app drew and checks itself (its own card's option, or a heard line its strict word list matches, judged on what the user said last), never from text a model, tool or file can write, nor from a plugin's message (a code plugin counts as annai's own); a model's verdict only decides what follows when that check finds none. A word list matches a line clause by clause, minus forms that can decline; a card's buttons end at its first answer. A late tap is an ordinary line; a tap answers by an id annai minted, never a provider's; a grant lives where it applies (the conversation's log), one an import brought is none, and what came from outside is marked as it comes in, so a standing "always" never reaches it. Words are read where they first exist, with when they began, on every path that carries them, not where a later step records them; copies of the same words are paired by their shared identity and ordered by when they happened, not by arrival, so a late copy reorders nothing. While someone is still speaking, an answer unsafe to act on waits; a decision the newest word settles waits for every line known to be heard, not for a timer; where her echo and a quick answer can't be told apart, the gate takes the side that can't grant by mistake; a rare setup's fix is a fallback behind the common path, measured too.
- **2026-11-10 Koe: a conversation with no dates has no plan to report, and a note ends Koe's own question**: a summary block says what its source can't know, never an empty value that reads as "none"; a wait on someone who may never answer yields to what must be said now.
- **2026-11-10 a sleep beside a failed call doesn't end her turn, and a note to Koe after one isn't sent; 2026-11-10 What a Stop stopped and what Koe answered owe nothing on reopening; what an open cut is taken up; 2026-11-10 Koe's notes Kokoro doesn't take up on purpose are written as settled**: work cancelled, let go or set aside on purpose is recorded where it is known and where the restart rule reads it, through the plain path's step, settling nothing else and true for all it covers, with a value of its own that older readers handle the same; a cut is said as what it was, by the code that knows, and marked in a field every result carries, so a result without it is an older page's, read by that page's rule; readers decide from records and fields, never from a result's words; a reader that takes over two owners' records owes what either still owed, each until that owner's answer; an end or a "done" sent with the work, or asked for by a model, is a plan: it counts once it happened, and after a failed step it waits for its sender to see the failure; bound every retry a failure buys by a count, not by spotting repeats; a note names only the cause annai knows.
- **2026-11-10 annai: "Shiori set the dates" stays as a record, and only its Undo follows the dates**: a line a person reads back tells an event, so it stays where it happened; only the action it offers follows the present, and goes (or says it was used) when nothing is left to act on. Read both from the log of what happened.
- **2026-11-10 annai: the microphone proves its audio thread runs, and the Trace dates the sound's context**: a state a platform reports ("running") is a claim, not proof: wait, bounded, for the first thing the work itself produces, and act on its absence; record beside the state something that must move while it is alive, so a failure can be dated. A record copies the fields it needs from a value, never spreads one whose shape grows: a new field can take a key the record already has.
- **2026-11-10 Koe reads Kokoro's words for the user when her note only points at them**: when one writer fills two fields for two readers and one is a fallback, a reader that can't see the fallback gets it whenever its own field can't hold the content; don't rely on the writer repeating itself. Measure such a threshold on both sides: "shorter" alone caught paraphrases.
- **2026-11-10 Kokoro's turn for a typed line waits for Koe's first words; 2026-11-11 Kokoro waits for Koe's answer live, and to reminders**: when a model is to act only if another party hasn't, let it decide after that party's first answer, for every input both get and on every path, bounded by how long that path's answer measurably takes; a condition checked before its evidence can exist always reads "not yet".
- **2026-11-10 Kokoro reads what Koe changed**: when two agents can each change the same state, each reads the other's changes as records the program wrote, from what the change returned, not from the other's account of it.
- **2026-11-10 A list of the conversation's root says the other trips are in list_trips; 2026-11-10 A conversation's given name stays unless they ask**: what a model needs to decide goes where it reads it when it decides: a fact it needs to say "it isn't there", in the result it reads then, for the callers that can act on it (a rule at the end of the system text is read before the question exists); when it may change something in one case and not another, both cases, since silence about the second reads as permission.
- **2026-11-10 Koe says a note's cautions too; 2026-11-11 Koe passes on what the user said, as they said it**: when a model relays text and part of it is a warning, name that part in the relay rule; a smaller model trims the end of what it relays first. Tell a voice model what to do, not a state (it says its name aloud); name the safe default for the rest; drop a rare-case line the program handles: it gets used where false.
