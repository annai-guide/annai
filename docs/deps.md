# Third-party code

What annai ships that it didn't write, why, what it uses of it, and what to watch for (the engineering rules, "Dependencies"). annai's own code (`src/`, `sw.js`) has none.

## PDF.js (pdfjs-dist 6.4.299, legacy build)

- **Where:** only in the official PDF pages plugin, `plugins-official/pdf-pages/vendor/pdfjs/`, copied unchanged from the npm package. Nothing under `src/` imports it, and nothing loads until a PDF needs drawing: the plugin imports it on its first `pages()` call, never at `activate`. Someone who doesn't install the plugin never downloads it.
- **Why:** drawing a PDF page needs a whole renderer (content streams, embedded font programs, compressed images, encryption), far beyond a few hundred lines of our own. No browser API draws a chosen page to a canvas: Safari's `<img>` draws page 1 only, and other browsers' viewers are frames a page can't read. PDF.js (Mozilla) is pure JavaScript, the most widely used and maintained choice, and runs in every browser annai supports. PDFium or MuPDF compiled to WebAssembly would be larger, and annai's CSP (`script-src 'self'`, no `'wasm-unsafe-eval'`) refuses WebAssembly.
- **Source and integrity:** `npm pack pdfjs-dist@6.4.299` (published 2026-10-03), tarball `sha512-AVl138zALtfaAPvADulE0PZThbYzCBS79nL4pOSL/6Sm/4AH5A21BD9VHt97OlCuzJuCpmeZtAtkinisF4Vb1g==`, the same as the registry's `dist.integrity`.
- **Licences:** Apache-2.0 (`vendor/pdfjs/LICENSE`). The standard fonts are Foxit's (`standard_fonts/LICENSE_FOXIT`) and Liberation (SIL OFL, `LICENSE_LIBERATION`). The JPEG 2000 and JBIG2 decoders are OpenJPEG's and PDFium's, compiled to JavaScript (`wasm/LICENSE_OPENJPEG`, `LICENSE_JBIG2`, `LICENSE_PDFJS_*`).
- **What is shipped (198 files, about 4.4 MB):** `LICENSE`; `build/pdf.min.mjs` and `build/pdf.worker.min.mjs`, from the package's `legacy/build/` (it carries core-js polyfills for older engines); `cmaps/` (all 169 packed CMaps, for CJK PDFs whose fonts aren't embedded); `standard_fonts/` (all 16, with their licences); `wasm/openjpeg_nowasm_fallback.js` and `wasm/jbig2_nowasm_fallback.js` with their licence files. **Not shipped:** the source maps, the `.wasm` files (the CSP refuses WebAssembly), `quickjs-eval.*` (PDF scripting), `pdf.sandbox`, `iccs/` and `qcms_bg.wasm` (ICC colour management, WebAssembly only), `image_decoders/`, `web/` (the viewer) and `types/`.
- **What we use:** `getDocument({ data, cMapUrl, cMapPacked: true, standardFontDataUrl, wasmUrl, useWasm: false, useWorkerFetch: false, enableXfa: false, verbosity: 0, isImageDecoderSupported: false })`, its `promise` (a `PDFDocumentProxy`: `numPages`, `getPage(n)`) and `destroy()`; `PDFPageProxy.getViewport({ scale })`, `render({ canvasContext, canvas, viewport }).promise` and `cleanup()`; `GlobalWorkerOptions.workerSrc`; the exceptions by `name` (`PasswordException`, `InvalidPDFException`). Each page is drawn on a white canvas and kept as a JPEG (quality 0.85).

### Quirks and pitfalls

- **It takes the caller's buffer.** `getDocument` transfers `data.buffer` to its worker, which leaves the caller's `Uint8Array` empty (a blob read from the store, a screen's Blob). The plugin hands it `bytes.slice()`. The browser suite checks the bytes are whole afterwards.
- **No `PDFDocumentProxy.destroy()` in 6.x.** The loading task owns the document: `task.destroy()` ends both, and the worker. It is what the plugin calls when it finishes, fails or is stopped (`signal` destroys the task).
- **`useWorkerFetch: false`:** the page, not the worker, fetches the CMaps and standard fonts (`DOMBinaryDataFactory`, a plain `fetch`). The page's requests always go through annai's service worker, which serves an installed plugin's files from the device (`/plugins/pdf-pages/…`). They are `application/octet-stream` (`.bcmap`, `.pfb`, `.ttf`), so `sw.js` serves that type, always with `nosniff`.
- **The worker:** a module worker made from `workerSrc` (`/plugins/pdf-pages/vendor/pdfjs/build/pdf.worker.min.mjs`). A browser whose service worker doesn't serve it, or a worker that fails to start, makes PDF.js fall back to its "fake worker": the same code imported and run on the page. Pages are still drawn, only on the main thread. A failed start disables real workers for the rest of the session (`PDFWorker.#isWorkerDisabled`).
- **The image decoders are imported from inside the worker** (`import(wasmUrl + 'openjpeg_nowasm_fallback.js')`, `WasmImage.#getJsModule`). Where the worker's own requests miss the service worker, JPEG 2000 and JBIG2 pictures are left out of the drawn page, with a warning; the text still draws. Approved as a known limitation (`docs/limitations.md`).
- **`isImageDecoderSupported: false`:** with the browser's `ImageDecoder` (WebCodecs), WebKit drew a scanned page's JPEG blank (measured with the `scan.pdf` fixture in Playwright's WebKit, 2026-10-28). PDF.js's own JPEG decoder draws it in every engine, a little slower.
- **`Promise.withResolvers`** is used unpolyfilled, in the page's code and the worker's, and needs Safari 17.4. On an engine without it the plugin adds a four-line shim and sets `globalThis.pdfjsWorker` to the imported worker module, so PDF.js runs its worker code on the page, where the shim is. iOS 16.4–17.3 is untested (approved as a known limitation); where PDF.js can't load at all, `pages()` says so in words ("This browser can't run PDF.js…") rather than crashing.
- **Errors are answers.** Anything PDF.js throws for a PDF (locked, broken, a bug it trips on) becomes an `Error` in plain words, so a bad PDF never counts against the plugin or switches it off. A password-locked PDF is not opened: annai never asks for its password.
- **No scripting, no XFA, no eval:** `enableXfa: false`, and the scripting sandbox isn't shipped. PDF.js 6 has no `new Function` or `eval` left in its builds (checked when vendoring), so annai's CSP refuses nothing it needs.
- **System fonts:** `useSystemFonts` stays on, so a non-embedded Helvetica is drawn with the device's own sans-serif where it has one, else from `standard_fonts/`.

### Updating it

1. `npm pack pdfjs-dist@<version>` in a scratch folder; check its sha512 against `npm view pdfjs-dist@<version> dist.integrity`; extract it into an empty folder of its own.
2. Read what changed in `legacy/build/pdf.mjs` for everything under "What we use", and the quirks above (search for `getDocument`, `class PDFWorker`, `BinaryDataFactory`, `WasmImage`, `withResolvers`).
3. Copy the files listed under "What is shipped", unchanged, over `vendor/pdfjs/`, and update this entry (version, integrity, file count and size).
4. Raise the plugin's version, then `npm run strings`, `npm run catalog`, `npm run stamp`.
5. Run the browser suite `pdf-pages` and `test/e2e/reading-files.spec.js` in both Chromium and WebKit.
